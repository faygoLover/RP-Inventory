# RP Inventory — план (2026-10-20, ответы Алекса учтены)

Свой мод ограничения инвентаря вместо InventoryFree, на RP Core. Старых игроков нет — переноса с InventoryFree не
делаем: InventoryFree убираем из сборки, заплатку `inventoryfree_keep_slots` — из RP Fixes.

## 1. Что не так с InventoryFree (зачем свой)
- Заворачивает слоты инвентаря игрока **в каждом меню** в свой `BlockedSlot` (подмена объектов). Меню, которые узнают
  слоты по классу, ломаются: альбом Exposure (чинили заплаткой RP Fixes 1.4.6).
- Подменяет только слоты **того, кто открыл меню**: при обыске в RP Medicine медик кладёт вещи пациента в его
  закрытые ячейки.
- Порядок наводит **задним числом**: раз в тик ищет вещи в закрытых ячейках и перекладывает.
- Рисует замки поверх ячеек (Алекса бесят). Ничего не знает о снаряжении; ёмкость — число из конфига плюс команда.
- Свой сетевой канал и свои данные игрока, параллельно RP Core.

## 2. Решения Алекса (20.10)
- **В1.** По умолчанию: хотбар 9, хранилище 9 (из 27) — как нынешние 18; броня (4) и вторая рука открыты.
- **В2.** Никакого жёсткого списка Curios. Спрашиваем Curios, какие типы слотов есть сейчас (со всеми модами), — по
  умолчанию **все открыты**; закрываем/ограничиваем **адресно** по типу, где нужно.
- **В3.** У рюкзаков (SA, Zero Contact) свой инвентарь — они слоты не расширяют. Но предметы-расширители слотов
  появятся. Снял расширитель, а места нет — **лишнее выпадает** из инвентаря.
- **В4.** Хотбар на экране **укорачивать и центрировать** по открытым ячейкам.
- **В5.** ГМы (op 2+) — без ограничений.
- **В6.** Снаряжения с бонусами пока нет. В будущем — ГМ-«зачарования»: ГМ вешает на предмет бонус без мерцания
  (+1 слот, +5% скорости, −10% выносливости…). Заложить: бонусы к слотам могут лежать в самом предмете (NBT).
- **В7.** С весом пока не связывать. Сейчас влияют: ампутант левой руки теряет слот левой руки; ампутант обеих ног —
  слот брони ног; особенности Организованный / Неорганизованный (+3 / −3 слота). Предложить остальное — §6.
- **В8.** Ампутация — да. Переломы, которые совсем не дают пользоваться рукой, — тоже (см. §6, как это устроено в
  медицине).
- Закрытые ячейки **скрыты полностью**: на их месте фон окна, будто ячейки нет. Никаких замков.
- Вещи **перераспределяются** нормально.

## 3. Что делает мод
1. Отдельно настраиваемые части: хотбар (из 9), хранилище (из 27), каждая ячейка брони, вторая рука, каждый тип Curios.
2. Закрытые ячейки не видны, не нажимаются, их место закрашено фоном окна.
3. Вещи никогда не попадают в закрытые ячейки. Ячейки закрылись — вещи переезжают в открытые; места нет — выпадают у
   ног (с сообщением).
4. Источники изменений: база из конфига, личная поправка ГМа, особенности (RP Perks), состояние тела (RP Medicine),
   бонусы в предметах (будущие ГМ-«зачарования»), датапак-модификаторы для предметов.
5. Работает в любом меню и для любого владельца инвентаря (обыск в медицине, чужие меню модов).

## 4. Как устроено

### 4.1. Закрытие ячеек без подмены слотов
- Миксин на ванильный `Slot`: `isActive()`, `mayPlace()`, `mayPickup()`. Если контейнер слота — `Inventory` игрока, а
  индекс закрыт **для владельца этого инвентаря** (`inventory.player`), слот неактивен. Неактивный слот ванильный экран
  не рисует и не даёт на него навести/кликнуть — скрыт в любом меню, объекты не подменяются (альбом Exposure работает).
- Ячейки пациента закрыты и для медика при обыске (владелец слота — пациент).
- Индексы `Inventory`: хотбар 0–8, хранилище 9–35, броня 36–39 (ступни, ноги, грудь, голова), вторая рука 40.
- Хранилище открывается **по порядку** (9, 10, … — слева направо, сверху вниз); хотбар — с 0.

### 4.2. Два вида закрытия
- **Снята** (ёмкость уменьшилась: конфиг, особенность, ампутация, снят расширитель) — вещи из ячейки уезжают в открытые,
  места нет — выпадают.
- **Заморожена** (временно: рука не работает из-за переломов) — вещь **остаётся** в ячейке, но её нельзя взять,
  положить, переложить, выбрать. Прошло — ячейка как была. Так перелом не вываливает вещи на землю.

### 4.3. Вещи не попадают в закрытые ячейки
- Миксины на `Inventory`: `getFreeSlot`, `getSlotWithRemainingSpace`, `add`/`placeItemBackInInventory` — закрытые
  индексы пропускаются (подбор, крафт, выдача модами, shift-клик).
- Хотбар: колесо и цифры **пропускают** закрытые ячейки; выбранная закрылась — переход на ближайшую открытую.
- Броня: надеть по ПКМ (`Equipable`, `swapWithEquipmentSlot`) и через другие моды — нельзя в закрытую ячейку.
  Вторая рука: клавиша F не работает, если вторая рука закрыта.
- Страховка раз в секунду: вещь в «снятой» ячейке → переложить и написать в лог, каким путём попала.

### 4.4. Перераспределение
- Порядок: досыпать в такие же стопки в открытых ячейках → в пустые открытые (сначала хранилище, потом хотбар) →
  выпадает у ног. Сообщение игроку над хотбаром («Не хватило места: N предметов выпало»).
- Броня/вторая рука закрылись — вещь из них так же: в инвентарь или на землю.

### 4.5. Скрытие на экране
- Неактивные слоты экран и так не рисует; остаётся рамка в текстуре окна. Закрашиваем её фоном: цвет берём **с самого
  окна** — один раз читаем пиксель панели рядом с ячейкой после отрисовки фона (работает с любым ресурспаком, включая
  тёмный ReimaginedGUI). Ячейка исчезает.
- HUD-хотбар: рисуем только открытые ячейки, полоска короче и **по центру**; выделение — по открытой ячейке.
- Творческий режим, наблюдатель и ГМы (op 2+) — без ограничений (настраивается).

### 4.6. Curios
- Список типов берём у самого Curios во время игры (`CuriosApi.getSlots()` с учётом всех модов) — жёсткого списка нет.
- По умолчанию все открыты. Конфиг/команда — закрыть тип или ограничить число: `back=0`, `ring=1`.
- Изменение — через собственные модификаторы слотов Curios (тип с 0 слотов Curios сам не показывает). Вещи из
  убранных слотов — перераспределением (§4.4).
- Команда `/rpinv curios` — какие типы есть сейчас и сколько открыто.

### 4.7. RP Core
- Розетка `InventoryProvider` в Core (по образцу `StaminaProvider`): `isSlotOpen(Player, index)`, `isSlotFrozen`,
  `capacity(Player)` (хотбар/хранилище/броня/рука/Curios), событие «ёмкость изменилась».
- Источники модификаторов регистрируют другие моды семейства через Core (как прибавки к выносливости): RP Perks —
  особенности, RP Medicine — тело. RP Inventory сам не знает про Perks и Medicine.
- Синхронизация — через общий канал Core (клиенту нужна итоговая ёмкость). Версия канала Core поднимается — сервер и
  клиенты переходят на новый Core вместе.

## 5. Настройки

### 5.1. Конфиг сервера (`rpinventory-server.toml`)
```
[base]
hotbar = 9            # 0–9
storage = 9           # 0–27
armor_head = true
armor_chest = true
armor_legs = true
armor_feet = true
offhand = true
curios = []           # адресно: ["back=0", "ring=1"]; не указан — как задали моды
[rules]
exempt_creative = true
exempt_gm_level = 2   # op 2+ без ограничений; -1 — ГМы тоже ограничены
```

### 5.2. Датапак модификаторов (`data/<ns>/rpinventory/modifiers/*.json`) — для будущих предметов-расширителей
```json
{ "item": "modid:pouch_belt", "worn_in": ["curios:belt"], "storage": 3 }
```
Сейчас список пустой (В6); формат готов.

### 5.3. Бонусы в самом предмете (будущие ГМ-«зачарования», В6)
- Читаем из NBT предмета ключ общего вида (например `RpBonuses: {inventory_storage: 1, inventory_hotbar: 1}`), когда
  предмет надет/в руке. Формат «зачарований» — общий для семейства (скорость, выносливость тоже), поэтому место ему в
  RP Core; RP Inventory читает только свои ключи. Сейчас закладываем чтение; инструмент ГМа — отдельной задачей.

### 5.4. Команды ГМа
`/rpinv show <игрок>` — итог и из чего сложился; `/rpinv set <игрок> <часть> <число>` — личная поправка;
`/rpinv reset <игрок>`; `/rpinv curios`.

## 6. Тело и особенности — предложение (на согласование)

| Источник | Эффект | Вид |
|---|---|---|
| Организованный (RP Perks) | хранилище +3 | снята/добавлена |
| Неорганизованный (RP Perks) | хранилище −3 | снята |
| Ампутация **левой** руки без крюка | вторая рука закрыта (если левша — рука, что держит вторую) | снята |
| Ампутация **рабочей** руки без крюка | медицина уже выбрасывает предмет из руки; хотбар не трогаем | — |
| Ампутация **обеих** рук без крюков | вторая рука закрыта; хотбар — только 1 ячейка (держать нечем) | снята |
| Ампутация **обеих** ног без протезов | ячейка брони **ног** закрыта; предлагаю и **ступни** | снята |
| Перелом руки, которая держит вторую руку (без сильного обезболивания) | вторая рука **заморожена** | заморожена |
| Переломы **обеих** рук (медицина: `armsDisabled`) | весь хотбар и вторая рука **заморожены** | заморожена |
| Нокдаун, путы (Cuffed / медицина) | хотбар и вторая рука заморожены | заморожена |

Как в медицине сейчас (проверено в коде 20.10): перелом **одной** руки только замедляет и ослабляет (руку можно
использовать); полностью руки отключены, только когда сломаны **обе** (и нет сильного обезболивания/адреналина), в
нокдауне или в путах. Отсутствующая рука без крюка — предмет из неё медицина сама кладёт в инвентарь (ячейки 9–35, без
учёта закрытых — после RP Inventory брать ячейку через Core).

Вес (В7) — **потом**. Идея на будущее: вес вещей в инвентаре → тратa выносливости через `StaminaProvider` (как вес
брони у RP Stamina), а не через слоты.

## 7. Связанные изменения в других модах
- **RP Perks:** сейчас Организованный/Неорганизованный меняют слоты **командой InventoryFree** (`Config.java`:
  `inventory_slots_command = "inventory_slots set_available {player} {value}"`, `Stat.INVENTORY_SLOTS`; админ —
  `ADMIN_INVENTORY_SLOTS = 36`). Перевести на розетку Core (источник модификатора), команду убрать.
- **RP Medicine:** обыск (`menu/SearchMenu`, `server/SearchService`) — закрытые ячейки пациента закроются сами (§4.1);
  для заглушки `BodyStubEntity` (свой контейнер) — спросить Core `isSlotOpen`. Выброс предмета из отсутствующей руки
  (`server/EffectsApplier`, конец `apply`) — класть только в открытые ячейки (Core). Регистрировать источник «тело»
  (§6). Находка записана в `RP Medicine/docs/test_findings.md` (20.10).
- **RP Fixes:** убрать заплатку InventoryFree (`mixin/inventoryfree/SlotBlockerMixin`, `fixes.inventoryfree_keep_slots`)
  после выхода RP Inventory.
- **S5 Packs:** убрать InventoryFree (`tools/add.py --remove inventory_free`), добавить rpinventory (common).

## 8. Порядок работ
1. Core: розетка `InventoryProvider`, источники модификаторов, событие, синхронизация.
2. RP Inventory: база из конфига, закрытие слотов (`Slot`/`Inventory` миксины), снятые/замороженные, хотбар (выбор,
   HUD короче и по центру), броня, вторая рука, ГМ/креатив.
3. Скрытие ячеек на экране (закраска фоном).
4. Перераспределение и страховка раз в секунду.
5. Curios через модификаторы Curios, команда списка типов.
6. Perks (особенности через Core), Medicine (тело, обыск, выброс из руки).
7. Датапак-модификаторы и чтение бонусов из NBT (формат согласовать).
8. Сборка: убрать InventoryFree и заплатку RP Fixes.

Проверка в игре — по плану, который даётся Алексу **перед** тестом (визуально проверяет он).
